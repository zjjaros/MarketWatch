MARKET WATCH - PROJECT ROADMAP
================================

Goal:
Build a small production-style application that tracks BTC and gold prices,
stores historical data, provides trend information, and is deployed to AWS
using Terraform.

Primary technologies:
- Python
- FastAPI
- PostgreSQL
- Docker
- AWS
- Terraform
- Git/GitHub
- CI/CD

Architecture goal:

                    Internet
                       |
                      ALB
                     /   \
                   API1  API2
                     \   /
                      RDS
                   PostgreSQL
                       ^
                       |
                  Collector
                       |
              External Price APIs


MILESTONE 1 - HELLO MARKET
===========================

Goal:
Build a tiny FastAPI application locally.

Tasks:
- Create FastAPI application.
- Create health endpoint.
- Create prices endpoint.
- Initially return hardcoded BTC/gold data.
- Run application locally.
- Test endpoints through browser or API client.

Example endpoints:
GET /
GET /prices

Concepts learned:
- FastAPI
- REST endpoints
- HTTP
- JSON
- Python project structure


MILESTONE 2 - GET REAL PRICES
=============================

Goal:
Replace hardcoded prices with real data from external APIs.

Tasks:
- Connect to a cryptocurrency price API.
- Connect to a gold price API.
- Make HTTP requests from Python.
- Parse JSON responses.
- Handle HTTP/network errors.
- Handle unexpected API responses.
- Set reasonable request timeouts.
- Learn how API keys/secrets work.
- Do NOT store secrets directly in source code.
- Add external dependencies using uv.

Current cryptocurrency API:
- CoinGecko

Important:
Do not bypass geographic/legal restrictions on APIs.
If an API is unavailable in our region, use another provider.

Concepts learned:
- External APIs
- HTTP requests
- Dependencies
- Error handling
- API authentication
- Secrets/configuration


MILESTONE 3 - POSTGRESQL
========================

Goal:
Persist price observations instead of only returning the current price.

Tasks:
- Add PostgreSQL locally.
- Design database schema.
- Create price observation table.
- Store BTC prices.
- Store gold prices.
- Add timestamps.
- Store the source of each observation.
- Add API endpoint for historical prices.

Initial table:

price_observations
------------------
id
asset
price
timestamp
source

Example endpoints:

GET /prices/current
GET /prices/btc/history
GET /prices/gold/history

Recommended Python technologies:
- SQLAlchemy
- Alembic

Concepts learned:
- Relational databases
- SQL
- ORM
- Database migrations
- Persistence
- Historical data


MILESTONE 4 - COLLECTOR SERVICE
===============================

Goal:
Introduce the first real microservice boundary.

Create two services:

1. API Service
   - Serves price data to users.
   - Reads from PostgreSQL.

2. Collector Service
   - Periodically retrieves prices from external APIs.
   - Writes observations to PostgreSQL.

Architecture:

External APIs
     |
     v
Collector
     |
     v
PostgreSQL
     ^
     |
    API
     |
     v
   Users

Tasks:
- Separate collector from API.
- Have collector retrieve BTC price.
- Have collector retrieve gold price.
- Store observations in database.
- Run collector periodically.
- Handle API failures gracefully.

Concepts learned:
- Microservices
- Service boundaries
- Background workers
- Scheduled jobs
- Service-to-database communication


MILESTONE 5 - TREND ANALYSIS
============================

Goal:
Provide useful information about historical price movement.

Add endpoint such as:

GET /prices/btc/trend?days=7

Return information such as:
- Starting price
- Current price
- Percentage change
- Highest price
- Lowest price

Eventually add:
- 24-hour change
- 7-day change
- 30-day change
- Simple moving average

Concepts learned:
- Data aggregation
- Time-series data
- Basic financial calculations
- API design


MILESTONE 6 - SIMPLE WEB UI
============================

Goal:
Create a small dashboard for Market Watch.

Display:
- Current BTC price
- Current gold price
- Historical charts
- Basic trend information
- Last update time

Keep the UI simple.

Do not turn this into a frontend engineering project.

Concepts learned:
- Frontend/backend interaction

MILESTONE 9 - DEV / TEST / PROD
===============================

Goal:
Create multiple environments using reusable Terraform code.

Environments:

dev
test
prod

Use reusable modules such as:

modules/
    network/
    compute/
    database/
    load_balancer/

Each environment should be able to use the same modules with different
configuration.

Example differences:

DEV:
- Small instances
- Minimal redundancy
- Lower cost

TEST:
- Similar architecture to production
- Moderate resources

PROD:
- Multiple API instances
- Higher availability
- Production-sized database

Concepts learned:
- Terraform modules
- Environment management
- Configuration
- Reusability
- Infrastructure scaling


MILESTONE 10 - FAILURE + DRIFT
==============================

Goal:
Intentionally break things and learn how the system behaves.

Exercises:

1. Manually change an AWS resource.
2. Run terraform plan.
3. Observe Terraform detecting drift.

Other exercises:
- Kill an API instance.
- Stop the collector.
- Break a security group rule.
- Delete a Terraform-managed resource manually.
- Run terraform plan.
- Run terraform apply.
- Observe what Terraform does.

Questions to answer:

- What happens when an API server dies?
- What happens when the collector dies?
- What happens when the database is unavailable?
- What happens when AWS infrastructure changes outside Terraform?
- What does Terraform state actually represent?

Concepts learned:
- Drift
- Reconciliation
- Failure modes
- Recovery
- Terraform state
- Infrastructure resilience


MILESTONE 11 - CI/CD
====================

Goal:
Automate testing and infrastructure validation.

Use GitHub Actions.

Pipeline should eventually:

1. Checkout code.
2. Install dependencies.
3. Run application tests.
4. Run Terraform formatting.
5. Run Terraform validation.

7. Eventually deploy changes.

Example Terraform checks:

terraform plan

Concepts learned:
- CI/CD
- Automated testing
- GitHub Actions
- Infrastructure validation
- Deployment automation

PROJECT ENGINEERING QUESTIONS
=============================

At every milestone, ask:

1. What problem am I solving?

2. Why did I choose this architecture?

3. What happens if this component fails?

4. What happens if the external service fails?

5. How would this scale?

6. How would I secure this?

7. What would I change if this were a real production system?

8. What does this technology actually provide that I couldn't easily
   accomplish with the previous architecture?

IMPORTANT DEVELOPMENT PHILOSOPHY
================================

Do not build the entire system at once.

At each milestone:
- Build something small.
- Make it work.
- Break it.
- Understand why it broke.
- Fix it.
- Then move to the next concept.

The goal is not to complete a tutorial.

The goal is to become capable of designing, building, deploying,
debugging, and explaining a real cloud application.
